# 智能体混合接入方案（知识库 + 实时工具调用）

> 赛道：科学研究和学科建设
> 接入策略：**知识库沉淀“方法论/术语” + 工具调用获取“实时数据”**，让智能体既懂量化分析逻辑、又能给出当日真实研判。

---

## 一、平台能力确认清单（去 aihome 先核对这 6 点）

在动手搭建前，登录 https://aihome.uibe.edu.cn 的“创建智能体”界面，确认平台是否支持：

- [ ] 1. **知识库上传**：支持的文件类型（txt/md/pdf/docx）、大小上限、是否支持切片/向量检索
- [ ] 2. **自定义工具**：能否配置自定义 HTTP/API 工具（OpenAPI / function calling schema）
- [ ] 3. **工作流编排**：是否有多节点工作流（意图识别 → 工具 → LLM → 输出）
- [ ] 4. **联网/外网可达**：工具调用时，平台能否访问到**校内/外网**的 HTTP 地址（决定部署方案，见第五节）
- [ ] 5. **系统提示词**：是否可自定义系统/角色提示词、长度上限
- [ ] 6. **鉴权**：自定义工具是否支持在请求头携带 API Key/Token

> 若平台**不支持自定义工具**（只支持知识库），则本方案退化为“纯知识库方案”：把第六节的“方法论与术语”全部传为知识库，智能体基于知识库回答，牺牲实时数据。若**支持工具**则走完整混合方案。

---

## 二、智能体角色定位

| 项 | 内容 |
|---|---|
| 角色 | 面向高校科研与教学的**金融量化研究助手** |
| 目标用户 | 金融、经济、数据科学等专业的师生 |
| 解决的核心问题 | 海量异构行情/资讯数据“难及时采集、难清洗、难研判”，师生缺乏实时、可解释的量化分析工具 |
| 能力边界 | 市场情绪研判、市场宽度、板块资金流、机会/风险信号、次日方向研判、个股概览、相关资讯 |
| 明确不做 | 不构成投资建议；不推荐具体买卖操作；不涉及涉密/隐私数据 |

## 三、系统提示词（可直接粘贴）

```
你是一名面向高校科研与教学的“金融量化研究助手”，底层接入 StockPulse 实时量化数据与研判引擎。
你的职责是帮助师生高效完成金融数据的采集、分析与成果研判，用于教学演示与学术研究，不构成任何投资建议。

【能力范围】
1. 市场情绪研判：调用情绪工具，给出 A 股/全球情绪分并解释各因子贡献；
2. 市场宽度与板块：调用宽度/板块资金流工具，描述涨跌结构、领涨领跌方向；
3. 机会与风险信号：调用信号工具，列出机会/风险信号并附证据；
4. 次日方向研判：调用预测工具，给出涨/平/跌概率与置信度，说明依据因子；
5. 个股与资讯：调用行情/新闻工具，提供个股概览与相关资讯。

【回答规范】
1. 先调用工具获取实时数据，再基于数据作答；数据缺失时明确说明并提示稍后重试，不要编造数字。
2. 所有结论必须引用工具返回的具体数据点（如“A 股情绪 62 分，其中市场宽度因子贡献 X 分”），做到可解释、可溯源。
3. 区分“数据事实”与“模型研判”：模型预测须标注置信度与不确定性，不把概率当确定性结论。
4. 涉及个股或涨跌方向时，始终附加“仅供科研教学参考，不构成投资建议”。
5. 语言简洁专业，复杂数据用列表或表格呈现。
```

## 四、知识库内容规划（上传平台）

知识库解决“方法论与术语”的稳定性，让智能体在无工具调用或解释术语时也准确。建议整理为以下 4 篇文档：

| 文档 | 内容要点 |
|---|---|
| `01-量化术语表.md` | 情绪分、市场宽度、涨跌停、连板梯队、赚钱效应、量能比、主力资金、风险偏好、VIX、板块资金流等定义 |
| `02-指标方法论.md` | A 股情绪 8 因子及权重、全球情绪 6 因子及权重、次日预测 6 因子规则基线、信号引擎规则 |
| `03-研判口径与免责.md` | 结论引用规范、概率≠确定性、科研教学用途、不构成投资建议 |
| `04-常见问答 FAQ.md` | 典型问题与标准回答（“情绪分怎么算的”“预测靠谱吗”“数据多久更新一次”等） |

> 提示：知识库内容可由现有代码注释 + README 整理而来（`domain/sentiment/analyzer.py`、`domain/prediction/model.py`、`domain/signal/engine.py` 的 docstring 已含因子与权重）。

## 五、工具定义（把 6stockPulse REST API 封装为语义化工具）

现状 API 粒度较细（30+ 端点），直接逐个配置会很碎。建议**在 6stockPulse 加一层“智能体工具网关”**（新增 `/agent/tools/*` 或一份 OpenAPI 定义），把端点聚合为 6 个语义化工具，输出统一 JSON。下面是 function-calling 风格的 schema（可直接复制到支持该格式的平台）：

### 工具 1：get_market_sentiment（市场情绪）
```json
{
  "name": "get_market_sentiment",
  "description": "获取 A 股与全球市场情绪分（0-100）及多因子贡献。A股=市场宽度/涨跌停强度/连板晋级/成交量能/板块扩散/主力资金/指数趋势/新闻情绪；全球=股指风险偏好/VIX/美元/黄金/原油铜/全球新闻。",
  "parameters": { "type": "object", "properties": {}, "required": [] }
}
```

### 工具 2：get_market_breadth（市场宽度）
```json
{
  "name": "get_market_breadth",
  "description": "获取市场宽度：上涨/下跌家数、涨停/跌停家数、连板梯队与赚钱效应。",
  "parameters": { "type": "object", "properties": {}, "required": [] }
}
```

### 工具 3：get_market_signals（机会/风险信号）
```json
{
  "name": "get_market_signals",
  "description": "获取结构化机会(opportunity)与风险(risk)信号，每条含标题、摘要、证据链、置信度、严重级别。",
  "parameters": {
    "type": "object",
    "properties": { "direction": { "type": "string", "enum": ["opportunity", "risk"], "description": "可选，仅返回机会或风险" } },
    "required": []
  }
}
```

### 工具 4：get_next_session_prediction（次日方向研判）
```json
{
  "name": "get_next_session_prediction",
  "description": "获取次日大盘涨/平/跌概率与置信度（规则基线：情绪35%+量能20%+全球风险15%+主力资金15%+涨跌停比10%+指数趋势5%），附各因子与解释。",
  "parameters": { "type": "object", "properties": {}, "required": [] }
}
```

### 工具 5：get_sector_flow（板块资金流/领涨）
```json
{
  "name": "get_sector_flow",
  "description": "获取概念/行业板块资金流向与领涨板块，返回板块名、涨跌幅、资金净流入、领涨个股。",
  "parameters": {
    "type": "object",
    "properties": { "type": { "type": "string", "enum": ["concept", "industry"], "description": "concept=概念板块，industry=行业板块" } },
    "required": ["type"]
  }
}
```

### 工具 6：get_stock_overview（个股概览）
```json
{
  "name": "get_stock_overview",
  "description": "获取单只股票的实时行情、分时/日 K 概览与所属板块，入参为股票代码或名称。",
  "parameters": {
    "type": "object",
    "properties": { "symbol": { "type": "string", "description": "股票代码（如 600519）或名称（如 贵州茅台）" } },
    "required": ["symbol"]
  }
}
```

**可选扩展工具**（按平台与时间允许再加）：
- `get_market_news`（新闻/公告，`/api/news`、`/api/announcements`）
- `get_ai_briefing`（AI 简报，`/api/analysis/briefing`）
- `get_intraday`（指数分时，`/api/market/index/{symbol}/intraday`）
- `get_fund_flow_top`（资金流排行，`/api/fund-flow/top`）

## 六、工作流设计（平台编排）

```
用户提问
   │
   ▼
① 意图识别：判断能力域（情绪 / 宽度 / 板块 / 信号 / 预测 / 个股 / 新闻）
   │
   ▼
② 工具调用：命中对应工具，向 6stockPulse 网关请求实时结构化数据
   │
   ▼
③ 数据整合：工具返回 JSON → 按知识库“指标方法论”归一化/取数
   │
   ▼
④ 研判生成：LLM 按“回答规范”生成结论（引用数据点 + 标注置信度）
   │
   ▼
⑤ 输出：结论 + 数据依据 + “仅供科研教学参考，不构成投资建议”
```

> 若平台工作流不支持复杂编排，可用“系统提示词约束 + 让 LLM 自主决定调用哪个工具”替代，效果接近。

## 七、部署要求（关键：API 必须对平台可达）

现状 API 只在本地 `127.0.0.1:8900/8902`，aihome 平台无法访问。三选一：

| 方案 | 做法 | 稳定性 | 适合 |
|---|---|---|---|
| A（推荐） | 部署到校内可达服务器/机房（校内 IP），平台工具指向该地址 | 高 | 正式参赛 |
| B | 内网穿透（frp/cpolar/ngrok）映射到公网 | 中（依赖隧道） | 快速验证 |
| C | 仅用知识库（若平台不支持工具） | 高 | 兜底 |

**安全建议**：
- 工具网关只暴露**只读 GET**工具（情绪/宽度/信号/预测/板块/个股），**不暴露** `POST /api/crawl/*` 等写接口；
- 网关加鉴权（请求头 `Authorization: Bearer <token>`）+ 简单限流；
- 不接入任何涉密/隐私数据，符合大赛内容要求。
