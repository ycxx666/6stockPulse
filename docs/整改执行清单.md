## 6.0 架构决策(已定,勿偏离)
- **平行界面形态 = 独立 HTML 多页 + 公共层**:每个界面一个 `frontend/*.html`;公共样式/脚本抽到 `frontend/css/base.css` 与 `frontend/js/common.js`,各页引用。
- 依据:后端 `app/api/server.py` 已把整个 `frontend/` 目录静态挂载(加文件即生效,零后端改动);现状 `index.html` 为 1070 行无外部依赖单文件,继续塞视图会指数级膨胀与冲突。
- WS:`/ws/realtime` 后端已实现(worker RealtimeService 3s 推送),`CONFIG.wsUrl` 已定义未用 → 界面先维持 30s 轮询,接 WS 作为优化项(6.4)。

## 6.1 危害与对策(做新页面时必须遵守)
| 危害 | 对策 |
|---|---|
| 单文件继续膨胀(1070 行全内联) | 拆公共 css/js,每页只留专属部分(见 6.3 拆分) |
| 全局 id/函数/变量跨页冲突、互相覆盖 | 页面内新增全局命名加前缀(如 `idx-`/`glb-`),公共函数只放 common.js |
| 端点表/工具函数/时钟/连接状态重复粘贴、版本漂移 | common.js 单一来源,页面统一引用 |
| 样式不一致、主题改不动 | 主题变量与通用组件样式统一在 base.css |
| nav 入口(现 6 键 disabled)再变假按钮 | 已就绪页做真实链接(锚到各自 html),未就绪保持 disabled+title;激活态按 `location.pathname` 判定 |
| 新页面重犯旧错(演示壳/内联假数据) | 约定:只用真实 API、空数据先显空态、innerHTML 一律 `escapeHtml`(函数在 common.js) |
