## 二、发现的问题与修复明细

### 问题 1（严重）：`000001` 代码冲突——平安银行冒充上证指数

**根因**：`stock_prices` / `latest_quotes` 中的 `stock_code='000001'` 是**平安银行（深市）**；而上证指数在 `market_quote_snapshot.symbol='000001.SH'（由 `collect_sina_all.collect_indices` upsert 维护）。多处代码把前者当作"大盘/指数"使用。

**线上实锤**（修复前）：`GET /api/market/volume-comparison` 返回的分钟序列 `close≈11.6x`（平安银行股价），而非上证指数的 3700+ 量级。

| 位置 | 原行为 | 修复 |
|---|---|---|
| `services/prediction_service.py::_get_index_change` | 取平安银行涨跌幅，生成"大盘下跌1.63%"等错误解释（调度任务写入 prediction_result） | 改查 `market_quote_snapshot WHERE symbol='000001.SH' AND is_stale=FALSE` |
| `services/sentiment_service.py::_calc_index_trend` | 用平安银行 5/20 日趋势充当"指数趋势"因子（权重 8%） | 改取新浪日线 `sh000001`（scale=240），结果缓存 300 秒；失败回落中性 50 |
| `application/market/analyzer.py::get_minute_volume_comparison` | 平安银行分时量 + `SUM(amount)` 全表汇总（分钟明细重复求和，成交额放大约千倍） | 改取新浪上证指数分钟线（sh000001）；上一交易日自动跳过周末/节假日；总额=分钟 amount 增量求和（实测：今累计 5334 亿 vs 昨 6870 亿，口径自洽） |
| `application/market/analyzer.py::get_index_intraday` | 新浪失败时回落 `stock_prices`（=平安银行分钟线冒充指数分时） | 移除该回落，失败返回空（前端显示空态，不编造） |
| `domain/prediction/model.py::_get_index_change` | `market_quote_snapshot` 查询无 `ORDER BY`，多指数时返回随机行 | 精确匹配 `000001.SH` + `ORDER BY quote_time DESC`，逐级回落 |
| `services/market_service.py` 旧树同名函数 | 同上两组 bug | 统一委托 `application.market.analyzer` 实现（单一事实源） |

### 问题 2（中）：涨停/跌停家数不分板块，阈值扁平 `change_pct >= 9.95`

**根因**：A 股涨跌幅限制分板块——主板 10%、主板 ST 5%、科创板/创业板 20%、北交所 30%。扁平 9.95 导致：创业板股票 +10%（未涨停）被误计为涨停（多计）；主板 ST +5% 涨停不被计入（漏计）；连板梯队同样失真。

**修复**：6 处查询全部改为板别阈值 `CASE`（LEFT JOIN `stocks` 取 stock_name 判 ST）：

```
LEFT(stock_code,3) IN ('688','689','300','301') → 19.95   # 科创/创业板(含其ST)
LEFT(stock_code,1) IN ('4','8')                → 29.95   # 北交所
stock_name LIKE '%ST%'                         → 4.95    # 主板ST
ELSE                                           → 9.95    # 主板
```

涉及：`application/market/analyzer.py`（宽度+连板梯队+赚钱效应选样）、`services/market_service.py`（宽度+连板梯队，旧树连板梯队改为委托 analyzer）、`application/dashboard/aggregator.py`、`app/api/routes/market.py`（/api/fund-flow）、`services/dashboard_service.py`、`api/routes/market.py`。

### 问题 3（中）：全市场成交额汇总把分钟明细重复求和

**根因**：`stock_prices` 是分钟级明细且 amount 为当日累计值，`SUM(amount) WHERE trade_date=x` 会把同一股票的累计额重复相加约千倍（线上 footer 曾显示"今累计 10.5 万亿"，全 A 真实日成交额约 1.5-2 万亿）。

**修复**：`get_volume_comparison`（新旧两树，sentiment 成交量能因子的数据源）改为每股取当日最后一条快照再求和：
`SELECT DISTINCT ON (stock_code) amount ... ORDER BY stock_code, trade_time DESC`。

### 问题 4（低）：旧树存在写死假数据

**位置**：`services/market_service.py::get_enhanced_profit_effect` 曾硬编码 `seal_rate=0.85 / break_rate=0.15`（TODO 占位）。

**实际情况**：线上 `/plugin/breadth`、`/api/short-term/heat` 走 `application/market/analyzer.py` 的真实计算（基于分钟数据判定封板/炸板，无样本返回空态），该写死值不上面；但为消除隐患，旧树函数已改为委托 analyzer 真实实现，写死值删除。

## 四、遗留事项（需人工关注）

1. **需要重新部署**：以上修复在本地代码库，线上服务器仍跑旧代码（表现为量能对比接口仍返回平安银行数据）。部署后复验 `/api/market/volume-comparison`（收盘价应为 3700+ 量级）。
2. **并发编辑冲突（重要）**：修复期间检测到文件夹被外部并发修改（疑似 IDE 内的 AI 助手在做"新旧树合并"重构），按函数粒度覆盖过本轮修复 3 次。已全部补回并通过验证；若再被覆盖，可用工作区备份 `6stockPulse_fixed_backup/`（10 个文件）一键恢复，或重跑 `verify_fixes.py` 检查。
3. **全球市场数据陈旧**：`/api/v1/dashboard/health` 显示 `global_market` 源自 10-19 14:04 后未更新（采集任务 `job_global_indices` / `job_seed_global_market` 需排查），全球情绪/海外指数展示会偏旧。
4. **"量能对比"为全日累计对比**：`get_volume_comparison` 今日（进行中）vs 昨日（完整日）非严格"同时刻"对比，盘中会系统性偏低；情绪分"放量/缩量"判读宜知悉此口径。
5. **旧树 `api/` 路由为死代码**（入口 main.py 走 `app.api.server`），其 `get_minute_volume_comparison` 曾含同款平安银行 bug——本轮未改死代码路由本身，但旧树 service 函数已全部委托新树，隐患已消除。
6. **赚钱效应样本依赖分钟数据**：仅实时跟踪的 TOP100 股票有分钟明细，"昨日涨停今日表现"样本可能不完整（空态时前端显示"暂无样本"，不编造）。
